# Первый выпуск и обновления «Толка»

В проекте уже подготовлен бесплатный механизм обновлений через GitHub Releases и Sparkle. Репозиторий выпусков: https://github.com/vihlyanec/tolk. Открытый ключ и адрес канала настроены в Release/updates.json; закрытый ключ хранится в Связке ключей этого Mac. Первый выпуск 1.0.0 (сборка 24) опубликован: https://github.com/vihlyanec/tolk/releases/tag/v1.0.0. Публичный подписанный канал доступен; установленное приложение успешно проверило наличие новых версий.

## Как это работает

Ты меняешь приложение → собираешь ZIP → создаёшь черновик выпуска на GitHub → проверяешь → публикуешь. Установленный «Толк» читает ленту последнего выпуска, предлагает обновление, проверяет цифровую подпись, заменяет приложение и перезапускает его. Задачи и заметки находятся отдельно от приложения и сохраняются.

Пользователь может выбрать «Толк → Проверить обновления…» или включить автоматическую проверку в настройках. Установка требует его согласия. Сервер, App Store и платный хостинг для этого варианта не нужны.

## Что важно без Apple Developer

Этот путь бесплатный, но приложение пока не имеет Developer ID и нотариального заверения Apple. На другом Mac установка из интернета может быть заблокирована Gatekeeper, в том числе после обновления. Мы не отключаем системную защиту и не обещаем установку без предупреждений. Инструкции Apple: https://support.apple.com/102445.

Цифровая подпись обновлений Sparkle — отдельная вещь: она подтверждает, что обновление выпустил владелец ключа. Она не заменяет заверение Apple. Перед широким распространением стоит перейти на Developer ID и notarization. В этом случае сам механизм GitHub/Sparkle менять не понадобится.

## 1. Создать репозиторий (уже выполнено для vihlyanec/tolk)

1. Войди в https://github.com и нажми «+ → New repository».
2. Название: `tolk` (можно другое). Выбери **Public**: приложению нужен доступ к выпускам без чужого GitHub-токена.
3. На первом шаге не добавляй README, .gitignore и лицензию: файлы проекта уже подготовлены.
4. Нажми Create repository и скопируй ссылку.

Public означает, что загруженные исходники видны всем. Если исходники нужно оставить закрытыми, до первой загрузки нужно отдельно настроить приватный репозиторий разработки и публичный репозиторий выпусков. Текущая инструкция рассчитана на один публичный репозиторий. Лицензию своего кода владелец выбирает отдельно.

## 2. Один раз настроить ключ и адрес обновлений (на этом Mac уже выполнено)

Открой терминал в папке проекта. В примерах замени `YOUR_LOGIN` своим GitHub-логином.

```sh
python3 scripts/release.py setup YOUR_LOGIN/tolk
```

Sparkle создаст ключ в **Связке ключей macOS**. Если система спросит разрешение на сохранение/доступ к этому ключу, разреши доступ инструменту Sparkle. `Release/updates.json` будет содержать только адрес репозитория и открытый ключ — этот файл можно добавить в Git.

Один раз сохрани резервную копию закрытого ключа вне проекта:

```sh
python3 scripts/release.py backup-key "$HOME/Desktop/Tolk-signing.ed25519"
```

Затем перенеси этот файл в защищённое хранилище и убери с рабочего стола. **Не загружай его в GitHub и не присылай в чат.** При потере ключа пользователям бесплатной сборки может понадобиться ручная переустановка, чтобы доверять новому ключу.

Не меняй адрес репозитория, имя `Толк.app`, bundle identifier или ключ между выпусками без отдельного плана миграции.

## 3. Первая загрузка исходников

В этой папке Git уже инициализирован. Пока все файлы локальные, удалённый репозиторий не подключён.

Сначала просмотри список файлов. Команда ниже добавляет код и файлы выпуска; личная база, сборки, внутренние заметки и временные эксперименты туда не входят.

```sh
git add .gitignore Package.swift Sources Tests Resources scripts .github Release README.md DISTRIBUTION.md THIRD_PARTY_NOTICES.md
git diff --cached --stat
git commit -m "Prepare Tolk releases and signed updates"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/tolk.git
git push -u origin main
```

При запросе GitHub войди своим аккаунтом. Не вставляй токен в исходники, URL репозитория или приложение. Если `origin` уже существует, сначала проверь `git remote -v`, не добавляй второй вслепую.

GitHub Actions после загрузки проверит тесты и сборку. Он **не публикует** приложение и не получает закрытый ключ подписи.

## 4. Подготовить первый выпуск (1.0.0 уже опубликован)

Первый публичный выпуск можно назвать `1.0.0`, номер сборки — `24` (сейчас локальная сборка 23). Версия видна человеку; номер сборки нужен обновляющему механизму и каждый раз увеличивается.

Скопируй `Release/notes.example.md` в `Release/notes-1.0.0.md`, напиши реальные изменения. Сохрани и отправь commit с этим описанием. Подготовка публичного выпуска требует чистых сохранённых исходников.

```sh
zsh scripts/test.sh
python3 -m unittest discover -s scripts/tests -v
python3 scripts/release.py prepare 1.0.0 24 --notes Release/notes-1.0.0.md
```

Появится папка `build/releases/v1.0.0`:

- `Tolk-1.0.0.zip` — приложение для Intel и Apple Silicon, macOS 14+.
- `appcast.xml` — подписанная лента обновлений.
- `Tolk-1.0.0.md` — описание изменений.
- `checksums.txt` и `manifest.json` — проверка целостности и привязка к исходному commit.

В ZIP только приложение. Ни задач, ни базы, ни закрытого ключа, ни токена там нет. Подготовка ещё ничего не загружает в интернет.

Проверь ZIP на отдельном Mac/тестовом пользователе: установка в «Программы», запуск, быстрый ввод, уведомления и чтение старых данных. Не заменяй личную рабочую копию непроверенной тестовой сборкой.

## 5. Загрузить черновик и опубликовать

Для команд загрузки нужен официальный GitHub CLI: https://cli.github.com. После установки выполни `gh auth login` и войди через браузер. Авторизация хранится средствами GitHub CLI; она не встраивается в приложение.

```sh
python3 scripts/release.py upload 1.0.0
```

Это создаёт **Draft**, а не публичный релиз. На GitHub открой Releases, проверь описание и файлы. Подготовленные файлы после подписи не редактируй.

Когда всё готово, нажми Publish release на GitHub либо выполни:

```sh
python3 scripts/release.py publish 1.0.0
```

Команда сверит контрольные суммы загруженных файлов и сделает выпуск последним (`Latest`). Адрес `releases/latest/download/appcast.xml` начнёт указывать на новую подписанную ленту.

## 6. Следующее обновление

Для примера следующая версия — `1.0.1`, сборка `25`:

1. Внести изменения; проверить Demo и тесты.
2. Записать изменения в `Release/notes-1.0.1.md`.
3. Сохранить и отправить commit на GitHub.
4. Подготовить, загрузить черновик, проверить и опубликовать:

```sh
python3 scripts/release.py prepare 1.0.1 25 --notes Release/notes-1.0.1.md
python3 scripts/release.py upload 1.0.1
python3 scripts/release.py publish 1.0.1
```

Номер сборки должен быть больше предыдущего. Уже опубликованные ZIP/ленты не заменяй другой сборкой с тем же номером. Если нашли ошибку, исправление выпускается с новой версией и большим номером.

## Проверка обновлений перед настоящим запуском

Нужны два настоящих выпуска с одним ключом: установить старый из релизного ZIP, опубликовать новый, выбрать «Проверить обновления…», установить и проверить версию и сохранение задач. Тестировать это нужно на отдельной копии с тестовыми данными. Публикация тестового выпуска в основной канал обновит его для всех, поэтому для таких испытаний нужен отдельный тестовый репозиторий и канал.

У нынешней локальной версии до подключения GitHub нет канала обновлений. Первый подключённый релиз потребуется установить вручную; последующие смогут приходить через Sparkle.

## Проверенные компоненты и реальные ограничения

Локально проверены тесты приложения, упаковка Sparkle, универсальный ZIP, подписи архива и ленты с временным ключом. Постоянный ключ и GitHub-репозиторий настроены. Настоящее скачивание и замена приложения через публичный GitHub проверяются после публикации двух тестовых выпусков. Публичный appcast проверен без авторизации, приложение 1.0.0 установлено в «Программы» и успешно показало сообщение о последней версии. Полная замена приложения переходом между двумя версиями пока не проверена. Нотариальное заверение Apple и реальный запуск на Intel Mac / macOS 14 пока не выполнены.

Официальные материалы: https://sparkle-project.org/documentation/, https://developer.apple.com/developer-id/, https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution.
