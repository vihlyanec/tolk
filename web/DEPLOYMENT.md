# VPS · ранняя вебверсия

Размещение подготовлено по прямому запросу пользователя на его VPS. Корневой пароль SSH не записывается ни в репозиторий, ни в конфигурацию. Существующие сервисы не переносятся и не перезапускаются контейнерными командами «Толка».

## Схема

Ubuntu 24.04 / x86_64. Существующий Nginx принимает HTTPS и направляет только выделенное имя на `127.0.0.1:18787`. Отдельный Compose-проект `tolk-web` запускает Gunicorn 26.2.0 в контейнере Python 3.13. Контейнер работает от UID 10001, с read-only корнем, отдельным томом данных, ограничениями CPU/памяти/PID и без capabilities.

Технический адрес: `https://tolk.103-102-229-153.sslip.io`. DNS sslip.io возвращает указанный в имени IP; это временный внешний DNS-провайдер, а не принадлежащий пользователю домен. TLS — отдельный сертификат Let's Encrypt. Замена на свой домен не требует переноса серверной базы, но меняет origin веб-приложения: перед переключением надо отправить старую локальную очередь, снова войти на новом адресе и заново установить PWA/подключить push, когда он будет реализован.

## Файлы на VPS

- `/opt/tolk-web` — исходники и Compose; server/public подключены к контейнеру только для чтения.
- `/opt/tolk-web/.env` — только HTTPS origin; режим 0600.
- `/opt/tolk-web/data/account.sqlite` — отдельная серверная база.
- `/opt/tolk-web/secrets/activation` — одноразовый код создания первого аккаунта; не входит в image или исходный архив; режим 0600.
- `/etc/nginx/conf.d/tolk-web.conf` — только виртуальный сервер «Толка» и отдельные rate-limit zones.
- `/var/lib/tolk-acme` — HTTP-01 проверка сертификата.
- `/etc/cron.d/tolk-web-backup` — ежедневная SQLite online backup в 02:23 по времени сервера.
- `/opt/tolk-web/data/backups` — максимум 14 последних копий, с quick_check и режимом 0600. Это локальная защита от повреждения/ошибок; отдельного внешнего резервного хранения пока нет.

Приватные TLS-ключи обслуживает штатный Certbot на VPS. Их содержимое агент не читает и не копирует. Настройки обновления других сертификатов не заменяются.

## Первый вход

Публичная регистрация отсутствует. Пока база пуста, форма требует код активации, имя и новый личный пароль от 12 символов. Код проверяется сервером; без него аккаунт создать нельзя. После первого аккаунта повторное создание блокируется транзакцией. Пользователь самостоятельно вводит личный пароль. Действующий пароль VPS не используется как пароль приложения.

Cookie `__Host-tolk_session` имеет Secure, HttpOnly, SameSite=Strict и Path=/; база хранит хеш токена. Срок сессии — 30 дней, есть отзыв через выход и повторный вход с сохранением очереди. Сервер проверяет точный Host и Origin, размер и формат запросов, ограничивает попытки входа. Никакие токены TickTick или данные основной SQLite на VPS не копировались.

## Обновление

Исходный пакет содержит только `server`, `public`, `Dockerfile`, `.dockerignore`, `compose.yaml`. Не архивировать `data`, `secrets`, `.env` или локальные тестовые базы. Перед обновлением сделать online backup. Менять только файлы приложения и перезапускать Compose-проект `tolk-web`, сохраняя data/secrets; для изменений зависимостей пересобирать image. Исходники подключены read-only с хоста, поэтому обычные правки не требуют повторной сборки базового образа. После запуска сверить контрольные суммы исходников внутри контейнера, HTTPS, auth boundary и восстановление резервной копии. Не выполнять `docker compose down -v`, очистку Docker или перезапуск посторонних стеков.

Для нового сервера предусмотрен `deploy/install-preview.sh`: он отказывается перезаписывать существующий каталог/виртуальный сервер, проверяет Nginx до reload и при невалидном TLS-конфиге возвращает собственный предыдущий HTTP-конфиг. Это установочный сценарий для конкретного согласованного Ubuntu VPS, не универсальный автоматический обновлятор.

## Ограничения

Размещается ранняя вебверсия. Нативный Mac-клиент, полный набор моделей, реальные интеграции, восстановление пароля, внешние backups и push ещё требуют отдельной реализации. Доступность страницы по HTTPS не означает завершённой синхронизации с установленным приложением или работающей доставки напоминаний.

Официальные источники: [Gunicorn deployment](https://gunicorn.org/deploy/), [Web Push на iOS](https://webkit.org/blog/13878/), [sslip.io DNS](https://nip.io/).

## Общий аккаунт, 6 ноября 2026

Текущая сборка добавляет полную модель Mac, pairing устройств и отдельный push worker. Перед обновлением сделать online SQLite backup и архив server/public/compose/Dockerfile; сохранить старый Docker image для отката. Сначала собрать новый образ в отдельной staging-папке, затем заменить только ресурсы проекта tolk-web. Не использовать down -v и не трогать соседние сервисы.

Перед запуском compose создать secrets/vapid.pem через push.create_key() внутри нового образа с bind mount только каталога secrets. Ключ создаётся create-once с mode600, owner10001. Не выводить его содержимое. Это отдельный ключ Web Push, не ключ Sparkle или TLS. После этого доступны web и push service. Существующие data/.env/activation сохраняются. Для заметок reverse proxy Толка требует client_max_body_size8m; проверить nginx -t перед reload.

Store выполняет только аддитивные миграции таблиц. При восстановлении серверной базы из старого backup обновить metadata.epoch на новый UUID; одного уменьшения cursor недостаточно во всех сценариях. Клиенты останавливают исходящие записи и предлагают явное сравнение. Журнал и idempotency receipts пока сохраняются без компактизации.

Нативное приложение необходимо обновить до версии с AccountService и подключить к тому же аккаунту через browser confirmation. Само размещение веба не подключает установленный Mac. TickTick и Apple Calendar требуют работающего Mac; восстановления пароля и внешних backups пока нет. Реальное разрешение и доставка push на iPhone проверяются пользователем после добавления PWA на экран «Домой».
