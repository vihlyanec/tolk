# Протокол общего аккаунта v1

Все операции авторизованы серверной сессией аккаунта; account ID не берётся из тела запроса. API доступен только с того же origin и JSON Content-Type. Ответы API не кешируются service worker и имеют Cache-Control no-store. Статические пути разрешены явным списком.

`GET /api/session` возвращает `{account: {id,name} | null, canSetup: boolean}`. `POST /api/setup` и `/api/login` принимают `{name,password}`. Setup возможен только для пустой базы при явно включённом режиме. `POST /api/logout` отзывает текущую серверную сессию.

## POST /api/sync

```json
{
  "cursor": 0,
  "operations": [{
    "id": "UUID операции",
    "entityID": "UUID записи",
    "kind": "task",
    "base": 0,
    "patch": {"title": "Задача"},
    "expected": {"title": null}
  }]
}
```

`kind` — task/project/tag/event/settings. ID записи settings равен ID аккаунта. UUID проекта/задачи независим от аккаунта, но все запросы/связи имеют серверную область аккаунта.

`base` — версия записи, на которой началась локальная правка, а не версия на момент нажатия «Сохранить». `expected` — исходные значения изменяемых полей. Оно позволяет последовательно отправить несколько собственных офлайн-правок одного поля без ложного конфликта. Отсутствующее поле представлено null. Если поле с момента base изменилось, текущее значение не совпадает ни с expected, ни с желаемым значением, возвращается конфликт. Независимые поля объединяются. Удаление записи, изменённой после base, и устаревшая правка удалённой записи требуют выбора. API не определяет победителя по часам устройства.

Ответ содержит `results` с `id`, `accepted`, `record` и при конфликте `fields`; `changes` — журнал версий записей аккаунта после cursor; `cursor` — номер последнего возвращённого изменения; `more` — необходимость следующей страницы. Каждая запись имеет `id`, `kind`, `version`, `data`. Страница — максимум 500 изменений; пачка — максимум 100 операций. Клиент отправляет не более одной операции на сущность в запросе, после конфликта останавливает зависимую очередь этой сущности.

Содержимое, версии полей, журнал изменений и подтверждение операции фиксируются одной SQLite-транзакцией BEGIN IMMEDIATE. Повтор принятой операции с тем же ID и идентичным содержимым возвращает прежнее подтверждение. Повтор ID с другим содержимым отвергается. Конфликт не считается применённой операцией: решение отправляется с новым ID и актуальной base. При ошибке валидации пачка полностью откатывается. Клиент сохраняет свою очередь до подтверждения и атомарно сохраняет ACK/новый курсор/кеш в одном объекте IndexedDB.

## Полная модель и восстановление

Передаются задачи и заметки со всеми полями Item, проекты, вложенные метки, порядок, настройки и общий текущий сеанс Помодоро. Schedule — атомарное поле: `{kind:"none"}`, `{kind:"day",day:"YYYY-MM-DD"}` или `{kind:"timed",instant: UnixSeconds}`. All-day сохраняет календарный день, timed сохраняет абсолютный момент при смене зоны. Прочие нативные даты используют стандартные секунды JSONEncoder с 2001 года. Старые date/time принимаются совместимым мостом в часовом поясе аккаунта; DST gap отвергается.

Первый запрос получает epoch сервера без отправки очереди. Последующие запросы передают epoch. Несовпадение epoch или курсор впереди журнала останавливает обмен; клиент сохраняет локальные версии, заново читает сервер и требует явного выбора различий. Mac перед этим экспортирует резервную копию. ACK проверяется по operation ID, entity ID, kind и подтверждённым полям. modified веб-задачи — серверные метаданные.

Страница ограничена 500 изменениями и приблизительно 2MB (одна большая запись допускается). Описание до 5MB, JSON-запрос до 8MB. Журнал и ACK пока не компактизируются; tombstones сохраняются. При ручном восстановлении базы администратор должен обновить metadata epoch, даже если восстановленный cursor не уменьшился.

## Подключение Mac

Native HTTPS `/api/device/start` создаёт одноразовую пару code/secret сроком 10 минут. Браузер с cookie читает сведения и явно подтверждает `/api/device/approve`; Mac получает bearer через `/api/device/poll` с secret ровно один раз. В базе хранится hash bearer. `/api/device/sync` и `/api/device/logout` используют bearer без Origin; браузерный sync по-прежнему требует cookie и точный Origin. Token хранится в Keychain с привязкой к origin и accountID. Отзыв устройства доступен в веб-настройках.

Ключи TickTick/Apple Calendar, нативная очередь интеграции и пути локальной базы не отправляются. Настройки провайдера содержат owner deviceID; операции внешнего сервиса выполняет этот Mac. Apple события передаются как read-only event с owner, без создания копий задач.

## Push

Подписки `/api/push/key|subscribe|unsubscribe` доступны только авторизованному аккаунту. Отдельный worker обрабатывает due reminders и конец фазы фокуса; квитанции предотвращают дубли, 404/410 удаляют подписку. VAPID-ключ создаётся один раз на сервере отдельно от Sparkle/TLS. На физическом iPhone требуется установка на экран «Домой» и пользовательское разрешение уведомлений; доставка на реальном устройстве ещё не подтверждена.

## Быстрая команда iPhone

Отдельные от устройств отзываемые ключи добавления и API capture описаны в SHORTCUTS.md. Они не дают читать/изменять существующие задачи. Доступны только создание новой задачи и справочники активных проектов и тегов своего аккаунта. Все записи проходят тот же журнал аккаунтной синхронизации.
